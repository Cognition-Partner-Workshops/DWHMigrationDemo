## Idioms
- Choose a distribution style per table: AUTO (the default), EVEN, KEY or ALL. ([source](https://docs.aws.amazon.com/redshift/latest/dg/c_choosing_dist_sort.html))
- Distribute the fact table and one dimension table on their common columns, choosing the largest dimension by data size. ([source](https://docs.aws.amazon.com/redshift/latest/dg/c_best-practices-best-dist-key.html))
- DISTSTYLE KEY needs a DISTKEY column, and only one column in a table can be the distribution key. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_TABLE_NEW.html))
- Declare COMPOUND, INTERLEAVED or AUTO sort keys in CREATE TABLE; a sort key can have up to 400 columns. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_TABLE_NEW.html))
- Leave column compression at ENCODE AUTO, which is the default for tables. ([source](https://docs.aws.amazon.com/redshift/latest/dg/c_Compression_encodings.html))
- Uniqueness, primary key and foreign key constraints are informational only and are not enforced, so keep data-quality checks in the load. ([source](https://docs.aws.amazon.com/redshift/latest/dg/t_Defining_constraints.html))

## Required replacements
- IDENTITY columns must be INT or BIGINT; replace SERIAL types and sequences with IDENTITY or GENERATED BY DEFAULT AS IDENTITY. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_TABLE_NEW.html))
- Identity values loaded by INSERT ... SELECT or COPY are unique, but Redshift skips values and the order might not match the source. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_TABLE_NEW.html))
- Replace unsupported PostgreSQL types such as arrays, BYTEA, JSON, MONEY, UUID, XML and the SERIAL family. ([source](https://docs.aws.amazon.com/redshift/latest/dg/c_unsupported-postgresql-datatypes.html))
- Store semi-structured data in SUPER, which holds up to 16 MB per value. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_SUPER_type.html))
- VARCHAR length is defined in bytes with a maximum of 65535, and a TEXT column is converted to VARCHAR(256). ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_Character_types.html))
- Rewrite unsupported PostgreSQL functions such as STRING_AGG, ARRAY_AGG, GENERATE_SERIES and REGEXP_MATCHES. ([source](https://docs.aws.amazon.com/redshift/latest/dg/c_unsupported-postgresql-functions.html))

## Unsupported constructs
- Table partitioning, tablespaces, indexes, triggers, sequences, table inheritance and full-text search are not supported. ([source](https://docs.aws.amazon.com/redshift/latest/dg/c_unsupported-postgresql-features.html))
- MERGE cannot use a WITH clause. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_MERGE.html))

## Procedural code
- Write stored procedures in PL/pgSQL with a dollar-quoted body and LANGUAGE plpgsql. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_PROCEDURE.html))
- Redshift does not support subtransactions, so exception handling is limited, and nested cursors are not supported. ([source](https://docs.aws.amazon.com/redshift/latest/dg/stored-procedure-constraints.html))
- Commands that need their own transaction context, such as VACUUM, CREATE EXTERNAL TABLE and ALTER TABLE APPEND, cannot run inside a procedure. ([source](https://docs.aws.amazon.com/redshift/latest/dg/stored-procedure-constraints.html))
- Use EXECUTE for dynamic SQL in PL/pgSQL. ([source](https://docs.aws.amazon.com/redshift/latest/dg/c_PLpgSQL-statements.html))
- NONATOMIC procedures commit each statement automatically; SECURITY INVOKER is the default. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_PROCEDURE.html))

## Security model
- Use role-based access control, which applies the principle of least permissions. ([source](https://docs.aws.amazon.com/redshift/latest/dg/t_Roles.html))
- Grant explicit privileges to roles; GRANT can also target PUBLIC and add WITH GRANT OPTION, so review both. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html))
- Never ship clear-text passwords; CREATE USER accepts MD5 or SHA256 hashes or PASSWORD DISABLE. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_USER.html))
- Authorize COPY with IAM_ROLE rather than access keys. ([source](https://docs.aws.amazon.com/redshift/latest/dg/copy-parameters-authorization.html))
- Set default privileges for future objects with ALTER DEFAULT PRIVILEGES. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_ALTER_DEFAULT_PRIVILEGES.html))
- Apply row-level security policies for row filtering. ([source](https://docs.aws.amazon.com/redshift/latest/dg/t_rls.html))
- SECURITY DEFINER procedures run with the owner's privileges. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_PROCEDURE.html))

## ETL and orchestration
- Bulk-load from Amazon S3 with COPY. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_COPY.html))
- Export query results to Amazon S3 with UNLOAD, which writes in parallel by default. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_UNLOAD.html))
- Query data in S3 through external tables. ([source](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_EXTERNAL_TABLE.html))
- Run SQL from orchestration code through the Amazon Redshift Data API. ([source](https://docs.aws.amazon.com/redshift/latest/mgmt/data-api.html))
